## 1. 背景与目标

项目初衷与本系统现状对照：

| 初衷能力 | 现状 | 结论 |
| --- | --- | --- |
| 对外界的信息收集 | 20+ 来源、事件管线、证据链完整 | ✅ 已达成 |
| 懂政治（利益相关方分析等） | `workbench_events.py:1054` `_political_intelligence()` 为关键词→固定模板 | ⚠️ 模板级，非推理 |

| 多 Agent 系统 | 11 节点流水线，仅 2 处用 LLM，无 Agent 间协议与记忆 | ⚠️ 流水线，非 Agent |

目标：一次性补齐四个缺口并跑回生产。效果优先——Agent 数量克制（4 个常设 + 1 个裁决），每个有真实推理与交叉验证机制。

### 1.1 非范围

- 不新增采集源登录/绕过（延续单操作者合规边界）

## 3. 目标架构（v2）

### 3.1 每日 LLM 预算（2026-10-06：HTTP 60 次/日硬顶，见 ADR-11）

| 阶段 | Agent | 调用数 | 用途 |
| --- | --- | --- | --- |
| 1 | 政治分析 | 16 | 当日热度最高 A/B 级事件逐个深度推理 |
| 2 | 历史类比 | 16 | 通过阶段 1 淘汰筛选的事件检索历史先例 |
| 3 | 品种合成 | 7 | 每品种一次，聚合证据出事件因子（D1/D7/D30 一次输出） |
| 4 | 质疑 | 7 | 每品种一次，反证检验与裁决 |
| 5 | 冲突裁决 | ≤2 | 仅当品种信号互相矛盾时启用 |
| — | 阶段请求合计 | **48** | 16+16+7+7+2；配额耗尽走模板 |
| — | HTTP 尝试硬顶 | **60** | 包含失败尝试和 schema 修复重试；12 次余量不自动花费 |

### 3.2 判断链路（六阶段）

- **阶段 0 输入装配**（无 LLM）：价格序列 point-in-time 冻结读取（复用 `capture_main_inputs` 机制）；近 7 天事件按 heat_score 取前 16，冻结输入集 SHA-256 入账；候选 0 时 B 阶段整体跳过，预测照常纯价格发出。
- **阶段 1 政治分析**（16 次）：逐事件输出利益方分析、权力结构、话语行为定级、执行概率（0-1+理由）、传导路径与滞后、逐品种方向+置信度。淘汰规则：执行概率 <0.3 且话语行为仅传闻级 → 不进历史类比。
- **阶段 2 历史类比**（8 次）：Top-3 历史先例 + 当时 D+1/D+7/D+30 实际轨迹 + 环境差异评估 + 经验先验（如"近 3 年 6 次类似制裁，D+7 原油 4 涨，中位 +1.8%"）。
- **阶段 3 品种合成**（7 次）：基准价格预测 + 存活事件政治分析 + 历史先验 → 逐品种事件因子（方向/强度/置信度 × D1/D7/D30）+ 依据链（引用事件 ID）。
- **阶段 4 质疑**（7 次）：反证库 + 跨品种传导一致性检查 → 维持/降级/推翻裁决；修正只能向保守方向（降强度或转 neutral）。
- **阶段 5 定案**（规则为主）：见 3.3。
- **阶段 6 账本与展示**：新表落库 + 预测页事件依据卡 + 复盘校准视图（结算与教训积累）。

### 3.3 定案规则（代码执行，无 LLM 消耗）

每个预测格最终 `direction` 由本节护栏规则裁定（ADR-9：定案方向即发牌方向）。基准为 neutral 而因子有方向时视为**分歧**情形（R2/R3 适用）：这是事件链发挥作用的主要场景——纯价格基准在 58-60% 天花板下几乎常为 neutral。

| 情形 | 定案结果 |
| --- | --- |
| 事件因子置信度 ≥0.6 且与基准同向 | 沿用基准方向，上调预测置信度（R1） |
| ≥0.6 且分歧（反向或基准 neutral），历史先验支持（方向一致且支持案例 ≥2） | 切换为事件方向（R2） |
| ≥0.6 且分歧，历史先验不支持 | 维持基准，记录分歧（R3） |
| <0.6 或因子为 neutral | 维持基准（R4） |
| 品种间信号矛盾传导断裂 | 触发冲突裁决 Agent（≤2 次/日），裁决后重跑定案规则（R5） |

### 3.4 降级语义

任何 Agent 调用失败/超时 → 重试 1 次 → 回退模板分析（UI 标注"模板级"）；B 阶段整体失败不阻塞发牌；预测保底永远是纯价格基准。预算超限直接走模板回退。

## 4. Agent 设计

### 4.1 单 Agent 七模块

| 模块 | 性质 | 职责 |
| --- | --- | --- |
| 角色宪法 | 固定 prompt | 身份、数据权限、硬约束（方向判断必须引用事件 ID；置信度 ∈[0,1]；禁止编造）、输出格式 |
| 输入装配器 | 代码 | 按 point-in-time 规则从黑板取数（`knowledge_available_at ≤ T`），打包 context pack + SHA-256。信息隔离在此层强制 |
| 工具箱 | 代码 | 预装配上下文为主；仅历史类比与质疑 Agent 有少量检索工具 |
| 推理核心 | LLM | `deepseek_client` 调用，stage 记账 |
| 输出合同 | 代码 | 每 stage 严格 JSON schema；校验失败重试 1 次 → 回退模板 |
| 自检门 | 代码 | 引用可解析、置信度边界、跨字段一致性 |
| 记忆接口 | 代码 | 读四层记忆；写只能写情景记忆（自己的产物） |

### 4.2 记忆系统（四层 + Mem0 混合架构）

| 层 | 归属 | 说明 |
| --- | --- | --- |
| 工作记忆 | 自研 | 当日 context pack，短暂但哈希留痕可重建 |
| 情景记忆 Episodic | 自研 | append-only：`agent_runs` + `event_agent_analyses`；结算后回填结果字段（对错/幅度差）——监督信号来源 |
| 校准记忆 Reflective | **Mem0 + 注册表** | 周度蒸馏 job（约 5 次调用/周，独立于每日 40）从已结算情景提炼教训 |
| 语义记忆 Semantic | 自研 | 现有 RAG / semantic_index / political_case_memory（只读） |

**Mem0 混合架构规则**：自研 `agent_lessons` 注册表是唯一事实源（教训 ID、依据 run_ids、valid_from、状态、撤销标记）；教训文本镜像进 Mem0 做语义检索。蒸馏产出 → 写注册表 → `mem0.add()`；prompt 装配时 `mem0.search()` → 注册表过滤（active 且 valid_from ≤ T）→ 注入。撤销 = 改注册表 + `mem0.delete()`。

**三条集成约束**：
1. point-in-time 过滤在 Mem0 之上（元数据字段 + 后过滤），回放 T 日只取 `valid_from ≤ T` 的教训
2. Embedder 统一用现有 `EmbeddingService`（fastembed 本地 ONNX）包装为 Mem0 自定义 embedder——全系统一条向量化路径，零新增外部 embedding 依赖
3. `mem0ai` 依赖进入极简 Alpine runtime，Dockerfile runtime-manifest 随之更新并过镜像体积检查

### 4.3 黑板通信协议（ADR-1、ADR-3）

Agent 之间不直接对话，全部通过落库产物交换。标准信封：

```
agent_artifact.v1:
{ run_id, producer, business_date, stage,
  input_refs: { context_sha256, event_ids },
  output: {…stage schema…},
  citations: [{type: "event"|"lesson"|"case", id}],
  confidence, fallback_used, model, prompt_hash, cost }
```

三种交互原语：

| 原语 | 行为 | 预算 |
| --- | --- | --- |
| 顺序交接（默认） | A 写黑板 → 编排器装配 B 输入 | 固定可算 |
| 有界返工环 | 质疑发现硬伤 → 打回合成修订重发 | 最多 1 轮/品种 |
| 冲突裁决 | 定案层检测跨品种矛盾 → 裁决产物 → 重跑定案规则 | ≤2 次/日 |

选择黑板+确定性编排器而非自由对话环的理由：预算可静态计算、回放可复现、每字节可审计、失败隔离。

### 4.4 记忆治理

教训自动发布（蒸馏 job 校验通过即生效），操作员随时可撤销；教训数量有界（活跃 ≤30 条）；不可手工编辑；每条必须引用具体情景 run_ids。`valid_from` = 所依据情景的结算日期。

## 5. RAG 与检索体系

### 5.1 现状三发现

1. **`political_case_memory` 是历史经验现成底座**：`storage.py` 建表 + `upsert_political_case_memory` + `build_political_case_memory.py`；字段（interest_map/power_structure/transmission_path/posterior_result/lessons/reusable_rules/event_type/affected_products/train_period/visible_at/confidence）几乎为历史类比量身定做；RAG 中 doc_type 权重 2.9，且在 `rag.py:1314` 被设为必需检索组。
2. **嵌入基础设施生产可用**：`semantic_embedding.py` fastembed 本地 ONNX（CPU、零 API 成本、导入不下载模型）+ hash_fallback 降级 + 禁混模式保护。
3. **检索已带可见性纪律**：`current_evidence_allowed(doc_type, observed_at)` + 每文档 `visible_at`。另 `llm_event_direction_judge.py` 已消费 RAG 做方向判断。

### 5.2 四消费者 + 一升级

| 消费者 | 检索内容 |
| --- | --- |
| 历史类比 Agent（新） | 主检索源：political_case_memory + 事件-价格配对库 |
| 政治分析 Agent（新） | 同主体/同类事件历史行为模式 |
| 质疑 Agent（新） | 反证检索（现有 counter-scan 已消费 `retrieve_evidence`，扩展） |
| 研判助手（现有） | 不变 |

**升级路径**：25 年回填产物统一写成 political_case_memory 格式——回填是给现有库扩容，不是另建库；`posterior_result` 从自由文本升级为结构化 D+1/D+7/D+30 实际价格轨迹。

### 5.3 设计决策

1. **混合检索**：结构化过滤（event_type/affected_products/环境标签，SQL）→ 语义排序（embedding）→ 附带价格轨迹
2. **统一 embedder**：全系统一条向量化路径 = `EmbeddingService`（fastembed ONNX）；semantic_index、RAG、Mem0 三消费者几何一致
3. **point-in-time 扩展**：回填文档 `visible_at` = 原始来源发布日期
4. **价格观测文档降位**：价格-事件配对进结构化层后，5,000 条价格观测文档保留仅作上下文
5. **检索质量评测并入 E 系列**：检索不到先例 → 类比输出标注"无先例"，禁止编造

## 7. 回测实验设计（E 系列）

### 7.1 E1 全链回放

隔离回放工作台（扩展 `scripts/experiments/replay.py`），按历史日期逐日重建 point-in-time 输入（事件按 `knowledge_available_at ≤ T`，价格 as-of T 冻结），跑完整 Agent 链 → 逐日 `event_adjusted_direction` → 对照实际结算。

- 抽样：按事件密度分层（零事件日/单事件/多事件日），品种×期限矩阵，目标有效样本 ≥200 格日
- 门禁：与现有 OOS 同标准（误差改善 ≥5%、方向 ≥55%、有效样本 ≥20），对照组=现行纯价格 `direction`，报告**增量贡献**
- 回放调用预算：独立一次性额度（≤600 次调用），每日取前 5 事件降配跑，断点续跑
- **回放只作淘汰性门禁：不过=淘汰；过了≠晋级**

### 7.2 E2 消融实验

仅特征工程（无 LLM）vs 仅 LLM 推理 vs 两者结合——回答"特征工程与 Agent 推理结合"的效果归因。

### 7.3 E3 污染测量

DeepSeek 训练语料包含历史，回放 2008 年时模型"已知"后续走势。对 LLM 训练截止前后两段历史分别回放，命中率差值即污染量级，写入报告作为回放结果的可信度修正项。**晋级依据为 25 年回放淘汰门禁 + 回测验收（ADR-6 经 ADR-9 修订：历史回放替代影子期）**。

### 7.4 检索评测（并入 E1）

历史类比 top-k 先例相关性抽查；检索不到先例必须输出"无先例"而非编造。

## 8. 信息隔离规则

### 8.1 三条时间线

| 时间线 | 定义 |
| --- | --- |
| `occurred_at` | 事件发生于世界的时间 |
| `knowledge_available_at` | 系统理论上可得知的时间（=原始来源发布时间） |
| `collected_at` | 实际入库时间 |

原生数据三者近似；**回填数据强制 `knowledge_available_at` = 原始来源发布日期**，禁止用 2026 年回填时间冒充。

### 8.2 point-in-time 输入集

T 日预测/回放只允许 `knowledge_available_at ≤ T` 的事件 + as-of T 冻结价格（复用 `capture_main_inputs`）；输入集 SHA-256 入账可审计。

### 8.3 LLM 权重污染缓解

(a) prompt 只喂 T 日前事实、要求事前（ex-ante）判断；(b) E3 两段对照测量污染量；(c) 晋级以历史回放验收为准（ADR-9 修订）。

### 8.4 结算与写入隔离

回放结算规则与生产一致，实际值取冻结序列，禁止用事后修订数据；回放只写隔离实验库，生产表与历史账本零接触。

## 15. ADR-9（2026-10-02，操作员批准）：单一发牌口径

**决策**：事件定案方向就是唯一发牌方向（`direction`），不存在第二套并行口径：

- OOS 正式门禁自动改为评判融合方向（它读的就是发牌 direction）
- 红线修订：原"direction 计算零改动"由本 ADR 取代；账本 append-only/门禁阈值/21 格合同不变

## 16. ADR-10（2026-10-02，操作员批准）：研判记忆与证据检索规范——一条主线

**决策**：推理链条自事件时点起一顺到底，每个环节的记忆与证据来源如下（拓扑 18 节点不变）——
1. **历史经验**检索统一研判记忆，三路供给：① 结构化案例匹配（7,209 条案例库，方向
   先验的计票来源）；② 索引召回：对入选事件做时点安全检索（仅召回 published_at <
   事件时点的段落），相似段落聚类为召回片段，可配同口径价格结果的升级为召回案例；
   ③ 复盘校准回灌的教训。召回案例取得方向计票权的精度门：同方向 ≥3 条独立段落互证
   且可配同口径价格结果，否则仅标注不计票。
2. **交叉质证**的反证检索证据架包含机制核验已转正事实（rule_checked）；与事件因子
   冲突 → 降级并标注，为空不阻塞。
3. **证据图谱页**是交叉质证与反证扫描环节的公开审计视图；**研判助手**是主线的读接口
   （虚线"随时可问"）。

**不变式**：21 格合同、OOS 门禁、定案规则 R1-R5+O1 护栏、点时纪律、账本 append-only
全部不变；索引检索为本地查询，Agent 调用预算零增量。

**验收（回测说话）**：召回案例计票权生效前，25 年回放须满足 Δpp ≥ 冠军 -0.5pp 且
D7 增益不消失、O1 D1 门控不可拆；不达标则召回案例仅标注不计票并记台账。

**P2 接口契约（与前端会话共议，2026-10-03）**：P2 不新增后端节点，18 节点契约冻结；
`/pipeline/graph` 响应新增非节点顶层块 `memory`（schema_version: pipeline-memory.v1）：
- `recall_enabled`（能力位，出处 `capability_source` 固定标注配置来源）——仅为能力，
  **不得推导运行成功**；
- 资源计数各带 `*_source` 固定出处：`index_docs`（语义索引）、`lessons_active`

## ADR-11 · 2026-10-06 预算容量调整

操作员要求调整。10 月 5 日 15 个存活事件中，历史经验 8 次配额用满，另 7 个事件走模板；HTTP 共 38 次。预算不是当日质量门阻塞根因。

此调整扩大历史分析覆盖；不是效果实验，旧冠军效果不作为新配额的因果证明。候选数、模型提示词、D1/定案规则、教训策略和正式晋级门不变。历史配额增加不会使品种研判返工可达（该阶段仍为7）。
