# 系统缺陷审计 + O1/O2 优化：v2 实验与期限门控（2026-10-01）

触发：操作员洞察"系统在未完善状态下跑了回测"——先例接线 bug 是同类缺陷的实证。

## 一、审计发现的三个同类缺陷（全部修复）

| 缺陷 | 现象 | 修复 |
| --- | --- | --- |
| **A 基准未进链路** | 生产 runner 与回放都没把价格基准传给合成/质疑 Agent（`baseline_by_product` 恒空，`disagreement_with_baseline` 失灵）——数据在系统里存在但没接线，与先例 bug 同类 | `compute_baseline_for_prompts()`：只读冻结标签序列 + 生产同款 robust 公式重算基准，生产 runner 与回放全部接线 |
| **B legacy 案例无真实后验** | 166 条 legacy 案例 posterior 全是占位文本（"该案例来自训练期事件…"）——先验闸门长期靠 T1/T2 支撑 | FRED 序列回填真实 D+1/D+7/D+30（整行 round-trip 防字段清空，幂等，166/166 完成） |
| **C 回放不传教训** | 回放工具不注入 active lessons | 空表暂无影响；蒸馏 job 落地后补 |

## 二、先验库升级（O2：从卡片到统计源）

- `compute_empirical_prior()`：从全库可见案例的**真实后验**算条件分布 `P(up|事件类型,期限)` + n + 中位涨跌幅度
- 类比 Agent 宪法升级：输出**分期限先验** `prior_by_horizon{d1,d7,d30}`（可表达"次日常反转、中期延续"），prompt 注入实证统计
- 融合层：`prior_by_event_from_chain_report` 输出分期限先验，R2 闸门按格子的期限取对应先验（legacy 单值先验兼容投影到三期）

## 三、v2 重验（同 60 日、同真实基线、n=180、LLM ~1,300）
