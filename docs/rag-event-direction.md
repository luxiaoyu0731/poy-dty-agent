# RAG 事件方向判断策略

本文件定义 POY/DTY 上游原料智能 Agent 如何用 RAG 和 DeepSeek 判断新闻事件方向。它是系统策略文档，会进入 RAG 检索，用来约束 AI 助手、事件判断脚本和预测复盘。

## 目标

事件方向判断回答三个问题：

1. 这个事件是否会影响上游成本压力。
2. 影响路径是原油、石脑油、PX、PTA、MEG、POY、DTY 中哪一段。
3. 当前证据是否足够进入预测账本或回测。

方向只允许使用：

- `利多`：倾向推高上游成本压力。
- `利空`：倾向压低上游成本压力。
- `中性`：影响不明确、互相抵消或暂时不构成成本压力变化。
- `不足以判断`：证据缺失、证据等级太低、证据过期或证据互相冲突。

## 正式口径

正式事件方向必须来自 DeepSeek + RAG。历史关键词规则、新闻标题关键词和旧的 `rule_direction` 只能作为审计字段，不能作为最终预测依据，也不能进入 LLM-only 命中率统计。

DeepSeek 每次判断前必须先检索 RAG。RAG 至少应尝试召回：

- 项目规则和价格口径文档。
- 新闻原文、新闻聚类和结构化事件。
- 数据源等级与证据质量。
- 利益相关方和行动能力。
- 传导机制。
- 产品价格链路。
- 价格观测和行业观测。
- 反证。
- 历史相似事件和预测复盘。

如果没有可引用证据，回答必须降级为“不足以判断”。

## as-of 安全

事件判断必须以 `as_of_time` 为边界。模型只能看到：

- `published_at <= as_of_time` 的新闻。
- `observed_at <= as_of_time` 的市场和行业观测。
- `created_at <= as_of_time` 的预测记录。
- 当时已经存在的项目规则和策略文档。

模型不能看到：

- 事件之后发布的新闻。
- 事件之后的价格。
- 事件之后生成的预测复盘结果。
- 后验命中率、错因和权重调整。

任何 as-of 判断都必须记录 `as_of_time`、检索证据、引用 doc_id 和 future leak 检查结果。

## 证据等级

证据等级决定置信上限：

| 证据结构 | 最高置信口径 |
| --- | --- |
| 至少一个 A 级事实锚点，且有价格或行业观测交叉验证 | 可以给出较高置信判断 |
| A 级事件，但缺价格或行业观测 | 可以给出方向性判断，不能给出强幅度判断 |
| B 级来源为主，有独立交叉验证 | 可以进入候选判断 |
| C 级公开媒体为主 | 只能作为弱信号，不能高置信 |
| D 级人工/Computer Use 观察 | 只能作为线索，必须人工确认 |
| title-only、正文过短、无 source_url、来源过期 | 降低证据等级 |
| 证据互相冲突 | 输出反证和缺口，通常降级为中性或不足以判断 |

如果检索证据全是 C/D 级，输出不能超过中低置信。

## 事件因果链

DeepSeek 判断时必须显式拆解因果链：

```text
新闻/事件
-> 利益相关方
-> 行动能力
-> 政策或市场机制
-> 产品价格链路
-> 价格观测
-> 反证
-> 判断方向
```

典型传导机制：

- 风险溢价：战争、封锁、制裁、航运安全事件可能推高原油和运费。
- 供应中断：装置检修、出口限制、港口延误可能推高对应产品。
- 运费/保险成本：航运风险可能推高到港成本。
- 库存变化：库存增加可能抵消成本上行。
- 开工率变化：炼厂、PX、PTA、MEG、聚酯工厂开工影响供需弹性。
- 汇率传导：美元和人民币变化影响进口成本。
- 需求抵消：下游采购延迟、订单走弱可能压制传导。
- 供应恢复：复产、增产、绕航恢复可能削弱利多。
- 风险溢价消化：市场已提前计价时，后续新闻不一定继续推涨。

## 利益相关方

涉及政治、制裁、航运和军事事件时，只能输出：

- 利益相关方是谁。
- 他们具备什么行动能力。
- 可能受益或受损的路径。
- 证据等级和反证。

禁止阴谋化表达，禁止把无证据的动机当成事实。

常见利益相关方包括：

- OPEC/OPEC+。
- EIA、IEA、能源监管机构。
- OFAC、Treasury、State Department、EU、UN。
- 伊朗、以色列、美国政府和军事护航相关方。
- 航运公司、保险机构、港口和海事机构。
- 炼厂、PX/PTA/MEG 工厂、聚酯工厂。
- 贸易商、下游客户和资金方。

## 反证要求

每个非中性判断都必须列出反证。常见反证包括：

- 需求走弱。
- 库存增加。
- OPEC 增产或供应恢复。
- 美元走强或宏观风险偏好下降。
- 价格没有跟随新闻。
- 现货缺少确认。
- 来源等级低。
- 事件已被市场提前计价。

如果反证强于主证据，应输出中性或不足以判断。

## 输出结构

事件判断应输出以下字段：

- `event_id`
- `as_of_time`
- `llm_direction`
- `confidence`
- `evidence_level`
- `reasoning`
- `counter_evidence`
- `cited_doc_ids`
- `affected_products`
- `stakeholders`
- `transmission_mechanisms`
- `risk_premium_decay`
- `demand_weakness_offset`
- `supply_recovery_offset`
- `should_enter_backtest`
- `needs_human_review`

`cited_doc_ids` 不能为空。为空时不得进入预测或回测。

## 人工确认

以下情况必须人工确认：

- C/D 级证据支撑的方向判断。
- title-only 或正文证据不足。
- 缺少 source_url。
- 涉及制裁、战争、封锁、重大政策的高影响判断。
- 影响 POY/DTY 但缺行业现货或库存确认。
- 回答中存在提示注入风险。
- 模型输出高置信但反证未充分处理。

人工确认不会把低质量证据变成高质量证据，只能说明该证据可以被研究使用。

## 进入预测账本条件

事件进入预测账本前必须满足：

- 有至少一个可引用 doc_id。
- 有清楚的产品链路或影响对象。
- 有反证说明。
- 有证据等级。
- 有 as-of 时间。
- 没有未来证据泄漏。

不能进入预测账本的情况：

- 只有模型常识，没有本地证据。
- 只有标题，没有正文或可靠来源。
- 只有 D 级人工线索且未确认。
- 价格窗口或影响对象不明确。

## 与前端展示的关系

前端展示“LLM 判断方向”，不展示规则版方向作为正式判断。技术字段如 `source_id`、`doc_id` 长列表、raw JSON、HTTP 状态、provider 和 token 只允许放在高级详情或审计模式中。

普通界面应显示：

- 事件标题。
- 中文摘要。
- 来源名称。
- 事件时间。
- LLM 判断方向。
- 置信度。
- 证据等级。
- 影响品种。
- 是否需要人工确认。
- 原文链接。
