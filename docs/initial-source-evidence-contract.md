# 首批来源证据合同

更新日期：2026-08-05（Asia/Shanghai）
适用版本：`source-evidence-contract.v1`

## 目的与边界

本合同让系统能够先安全运行授权数据的内部分析链，同时不把“能登录、能看到数值”误升级为正式预测资格。

- **运营输入**可以进入内部观察、事件研判、数据质量和成本压力的降级分析。
- **正式预测输入**必须另行通过 Phase A 的六项资格门禁和受信 manifest；本合同不改变当前 `eligible=0/19`。CFETS USD/CNY 是当前第19条正式换算证据序列，但尚未获批 manifest，且不产生独立汇率预测。
- 公网只能展示派生后的趋势、置信边界、数据缺口和解释；不得展示、导出或重建 CCF 原始报价。
- 账号、密码、Cookie、令牌和许可证原文均不得进入数据行、日志、报告、测试或 API 响应。

## 用户已决定的授权范围

当前 CCF 账号允许本项目：在正常登录和页面/导出权限范围内自动采集、内部留存、内部模型使用，以及对公网发布不可逆的派生结论。

用户同时决定：公开可访问数据一律按个人复用处理，后续无需逐来源再次申请项目内授权；此规则不允许绕过登录、付费墙、验证码、robots 或其他访问控制，也不替代正式预测输入所需的六项证据门禁和受信 manifest。

这是一项项目内部使用决定，不替代 CCF 条款本身。遇到验证码、二次验证、导出限制、页面权限变化或明确禁止的动作时，采集必须停止并保持数据缺失，不能绕过。

## 每次捕获必须保存的事实

每个原始观察或导出批次必须可追溯到以下字段：

1. `source_id`、供应商产品 ID/原始名称、固定语义 ID、规格、市场、报价类型、原始值和原始单位；
2. 观察日期、供应商发布时间（若可见）、页面/导出捕获时间、系统首次可见时间，以及来源 URL；
3. 原始页面/导出文件的 SHA-256、解析器版本、采集方式（正常页面、授权导出或人工上传）；
4. 不含凭据的账号/授权范围标识和本合同版本；
5. 标准单位、换算公式/版本及换算前后值；
6. 数据质量结果：规格匹配、单位有效、正值、时间顺序、重复检测和新鲜度；
7. 更正时的前一 revision 引用及更正原因。不得覆盖原行。

缺少原始哈希、捕获时间、规格、来源 URL 或授权范围标识时，行可作为排障线索，但状态必须是 `evidence_incomplete`，不能进入运营计算或正式资格评估。

## 修订与时间规则

- 每次采集生成不可变 capture 记录；同一来源/语义/规格/观察日期的新值或新证据创建 revision，不更新旧值。
- `observed_at` 是报价所归属的业务日；`visible_at` 是该值首次可由本系统确认获得的时间；`captured_at` 是实际采集时间。三者不得互相代填。
- 工作日 07:30 开始授权采集与校验，08:20 冻结晨报数据，09:30 仅发布已冻结内容。08:20 后的新数据只能形成带原因的 revision，不能覆盖原晨报。
- 任何 CCF 捕获失败、规格不一致、单位不明、页面验证阻断或超过新鲜度阈值，都必须显式降级，不得以前值、公开代理或推测数值补齐。

## 升级到正式预测输入的门槛

首批来源不是自动升级为正式输入。每个语义 ID 只有在以下事实被独立复核并进入受信 manifest 后，才可能通过正式资格：

1. 来源权限、规格/市场/报价口径、单位换算、新鲜度、可见性和交易日历六项均有有效证据；
2. 证据覆盖 D+1、D+7、D+30 所需期限，且有效期未过；
3. 行级修订链、原始哈希和首次可见时间能重放；
4. 产品公开输出仍只含派生结论；
5. 审批后的 manifest 摘要被部署进 `APPROVED_MANIFEST_DIGESTS`。

在上述步骤完成前，系统可运行运营级分析和降级晨报，但不得产生、写入或发布正式预测 batch。
