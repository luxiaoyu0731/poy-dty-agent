# POY/DTY 全应用使用与检测流程

版本：2026-09-08 v4。v1先编写后执行，v2补充交互，v3把补充项纳入正式矩阵，v4补充本轮真实运行、来源独立性与匿名访问的判定。入口：https://app.kaipingrc.com/ 。适用于单人工作台。

## 1. 操作方式与判定

先跑“看结论→核对行情→阅读事件→追溯证据→检查运行→提问→查看报告与复盘→工业情报”的完整路径，再做边界测试。生产只读与需要写入的操作分开；写入范围以本轮用户答复为准。不把旧报告或代码中存在控件当作已实测。

每个编号记录：环境、真实URL、前置条件、操作、期望、实际结果、截图/响应、通过/部分通过/失败/未验证、问题ID。每个独立按钮、标签、筛选、展开控件至少操作一次；数据列表覆盖首条、中间条、末条及分页边界。不存在或无数据的控件说明原因，不能写“通过”。页面日期以标注的上海时间或原始来源时区核对，价格必须连同币种、单位、报价基准和观察日期比较。

“100%中文覆盖”包括标题概述，不等于100%全文事实摘要。保留七产品（原油、石脑油、PX、PTA、MEG、POY、DTY）与1/7/30天预测；DCE、CCF软移除和EIA可选不是程序故障。

## 5. 实测后修订的操作规则

1. 筛选提交后，等待加载结束及列表总数稳定，再判断类别与结果。快速切换另外记录为竞态检测，不用中间态截图宣称筛选通过或失败。
2. 情报没有日报时，点“查看运行与来源”，先读任务失败原因，再检查来源。刷新只重新读取，不会生成日报。
3. 用 `intelligenceView=summary/radar/runs/map` 分享二级页面，验证刷新及前进后退。地图没有点位时，详情分支转隔离数据验证。
4. 图谱检索步骤没有对应节点时，应显示完整图和提示；点“适配视图”恢复。不能把画布空白解释成没有证据。
5. 行情放大后，横向滚动原料链核对所有品种、日期和单位；历史曲线与最新不同口径报价分开比较。
6. 新增 L05：分别下载账本 CSV、JSON，检查文件类型、21组合和非正式标识。正式批次不存在时，历史批次与到期复盘标为数据条件未满足。
7. I05补充：两张表分别翻页；展开来源“技术详情”；点“刷新运行记录”；失败记录应显示安全错误信息。
8. 新增 O05：展开模型详情和风险依据后收起；核对总览最新事件概述与事件页同一事件一致，不改变正文事实摘要资格。
9. 复制、下载、外链必须核对内容或目标；仅看到按钮不算通过。遇到登录、验证码或付费墙即停止并记录限制。
10. 写入测试每轮使用全新临时数据库目录。种子要求文件原先不存在，不能复用上一轮数据库或改用主库绕过保护。

## 7. v3验收执行规则（2026-09-07）

- 固定60个编号，逐项记录完整通过、部分通过、失败或未验证。页面覆盖和功能分支通过率分别报告。
- 每个请求等待最终成功、诚实空状态或明确失败；中间态只用于记录加载体验。不要在旧列表仍存在时认定筛选已通过。
- 追加列表后至少跨一次实际后台快照更新，检查条数、筛选与阅读位置。用户未操作时丢失追加结果单列问题。
- 每日摘要缺失时必须同时检查计划发布时间、运行审计与雷达；健康接口200不能覆盖业务任务失败。
- 每条只读失败允许正常重试一次；已取得可复现故障证据后继续其余模块，不把持续失败拖成无限验收。
- 无数据导致无法打开的抽屉、历史批次和到期分支，记录具体前置条件，标未验证；不能用模拟数据代替公网事实。
- 写入/计费操作按明确授权的具体范围执行；当前验收不新增抓取、生成、发布或主库操作。可单列后续隔离验收，未做就扣证据分。
- “验收报告完成”可以得出NO-GO；只有全部必要链路通过才可称“产品验收通过”。不以发布过代码、等待过自然日代替验收。
- 当前v3实测结果见 docs/full-acceptance-2026-09-07.md；此前报告保留为历史，不自动继承通过状态。


## 7. v4 修复后必须采用的验收规则

1. Agent 问答实际合同为检索、研判、复核、回答四阶段。12 项是全业务角色目录；不得把本轮未涉及角色判成缺失执行，也不得把目录节点算作成功。核对真实 run_id、四阶段终态、三次交接、实际模型调用次数；历史未知次数显示“—”。
2. AI “有返回”“外部模型实际生成”“引用支持主张”“正式质量门禁通过”分别记录。要求三句话时，另查回答是否遵守长度；不能仅凭字段完整判定质量通过。
3. L01 每个产品的 1/7/30 天共 21 格，逐格展开依据、技术诊断和 OOS 详情并关闭。记录有效样本数及未通过原因；0/21 通过不等于所有格样本数为零。读取失败另记程序/性能问题。
4. M03 至少实际悬停一个品种的首末点，截图必须含日期、单位、数值；其他品种未悬停的点明确未验证。本轮 POY 首尾已执行。
5. 来源独立性按原始事件 ID 核对，不能只比较域名。USGS 不同 eventpage ID 属于不同地震，不得作为同一事件的多来源互证。历史纠正采用追加修订并保留旧证据，不重写冻结日报。
6. C11 原生 Chrome 实际约 850px 窄窗口遍历八页与账本；图谱先适配画布，再滚动至判词和来源。隔离视口测试与公网截图分别记录。
7. G06 新无痕窗口如提示已有其他无痕窗口，不能宣称全新独立会话；只记录该窗口实际无登录进入，辅以不带 Cookie 的只读 HTTP 请求。禁止读取浏览器凭据。
8. C12 原生 DevTools 仅检查 Console 和 Network 状态、URL、耗时，不打开 Cookie/Storage。刷新中止的请求与加载稳定后的失败分别判断；一次无报错不等于全量网络通过。
9. I01 跨过零点但尚未到采集截止/发布时刻，今日摘要为空可合理；检查历史摘要可读。排序修复须等下一真实发布验证，不改历史日期来制造当日事实。
10. 用户已确认信息与证据报告独立生成。四类型逐项点击生成、核对列表/预览/来源链接/下载，刷新与跨类型返回后检查原编号。生成失败先读历史列表，不自动重复写入；正式报告资格仍单独校验。

最新修复、生产复验及未关闭项见《acceptance-closeout-2026-09-07.md》。本流程覆盖范围不代表每个生产分支已经通过，逐编号证据以 coverage-closeout.json 为准。

## 8. v5 修复后必须采用的验收规则（2026-09-08）

1. 性能预算（可复验）：AI 问答端到端 ≤ 30 秒（其中检索阶段 ≤ 10 秒）；七产品 OOS 评测读取服务端 ≤ 15 秒、命中短 TTL 缓存后重复读取 ≤ 3 秒；首次进入总览的 JS 传输量 ≤ 400KB（gzip，经公网实测）。以 DevTools Network 实测为准，样本为冷读一次加热读一次，不冒充 P95。
2. 首屏资源口径：入口 HTML 只预加载 runtime/antd/react/AgentWorkbenchPage；recharts（charts）分块只允许在行情模块渲染趋势图时加载，MapLibre 分块只允许在情报地图打开时加载（I06）。重复访问命中 immutable 缓存后，静态资源请求应显著减少；`/assets/` 响应必须为 `public, max-age=31536000, immutable` 且支持 gzip，`index.html` 保持 `no-store`。
3. R12 类问题不得用提高 warning 阈值或拆包游戏消除；验收以首屏传输量、重复访问请求量和交互结果证明。
4. G06/R13 独立会话证据：使用 Chrome 访客（Guest）窗口或全新用户配置目录，与既有无痕窗口不共享 Cookie；只记录该窗口实际可达功能，禁止读取浏览器凭据或用户配置。已有窗口共享会话的证据不算独立会话。
5. M03 图表判定补充：趋势图 过期 时画布内必须出现"历史序列截至 YYYY-MM-DD · 非当前报价"角标；合并的当前报价点 tooltip 必须标"价格（当前报价）"，与历史点可区分；数据新鲜度在最新报价与历史曲线不同基准时不得显示"fresh"。
6. AI 回答长度合规：问题含"N 句话/简短"约束时，回答只包含结论与可信边界；trace warnings 必须记录 `length_constraint_requested` 与 `length_constraint_trimmed`；被截断的回答其引用支持按截断后文本重新绑定，不得沿用原文引用冒充支持。
7. OOS 评测缓存口径：评测端点对相同 as_of 的结果缓存默认 60 秒（`SEVEN_PRODUCT_EVALUATION_CACHE_TTL_SECONDS` 可调）；验收需确认缓存命中响应与即时重算的 evaluation_id 一致（内容寻址），且门禁原因逐格诚实展示，不因缓存隐藏 0/21 或样本缺口。
8. R06 排序与发布判定：冻结历史摘要不重写、保持原排序；新排序（分数降序、时间降序、ID 降序）以下一次自然日真实发布的摘要为准，检查其 items 顺序与发布时间（计划 09:30，实际 released_at 如实记录）；发布延迟需同时读运行审计的失败原因，不以健康接口 200 混同业务成功。
9. 数据库只读连接判定：只读打开不得创建或遗留 `-wal`/`-shm` sidecar；写入竞态窗口内允许有界重试（≤4 次、150ms 间隔），重试耗尽仍失败才返回 `readonly_database_sidecar_state_invalid`。
10. 每条修复先公网复现（或引用本轮既有修复前证据），后按"根因→接受行为→最窄测试→回归→精确发布→公网复验"闭环；不允许以保留旧快照显示降级作为间歇读取故障的最终关闭理由。
