# ADR-0005：工业情报中心与空间态势层

- 状态：Accepted
- 决策日期：2026-09-05
- 实施状态：Pending；本 ADR 只冻结设计，尚未实现、迁移、部署或形成生产运行证据
- 价值状态：Pending；20 个预注册业务日实验尚未开始，且不阻塞首份按时非 `blocked` 日报后的技术交付
- 依赖：[`0001-seven-product-formal-forecast-contract.md`](0001-seven-product-formal-forecast-contract.md)、[`0002-seven-product-live-forecast-ledger.md`](0002-seven-product-live-forecast-ledger.md)、[`0001-api-versioning-and-security.md`](0001-api-versioning-and-security.md)、[`0002-llm-guardrails-and-evals.md`](0002-llm-guardrails-and-evals.md)、[`0003-production-readiness-boundary.md`](0003-production-readiness-boundary.md)、[`0004-public-benchmark-v2-and-ccf-soft-removal.md`](0004-public-benchmark-v2-and-ccf-soft-removal.md)
- 计划数据库迁移：v37 `append_only_industrial_intelligence_domain_v37`

## 背景

当前系统已经具备七品种预测、来源采集、新闻事件簇、RAG、证据追溯和每日工作台，但严格 OOS 证据只能随真实时间积累，现阶段预测对单一 POY/DTY 生产商的即时决策增量有限。操作者每天更直接的工作是发现分散在全球经济、地缘军事、制裁、能源、装置、航运港口、天气灾害和基础设施信息中的供应与采购风险，再判断其与原油、石脑油、PX、PTA、MEG、POY、DTY 的关系。

因此，产品价值重心调整为“工业情报整合与研判工作台”，预测继续作为独立参考能力。重排产品入口和新增情报能力，不等于改变预测科学合同：当前 7 品种 × D1/D7/D30 的定义、结果、状态、评分、API 语义和晋级规则必须保持不变，新情报在本决策下也不能成为预测输入或覆盖数值结果。

开源项目 [God's Eye View](https://github.com/bilawalsidhu/gods-eye-view) 提供了全球空间态势、多图层组织和交互展示的可借鉴实现，但其核心是空间可视化，不提供本项目所需的点时证据、事件聚类、产业链相关性、不可变审计和日报冻结合同。整仓合并、iframe 嵌入或作为第二套产品运行都会引入重复运行边界、技术栈分裂和数据条款继承不清的问题。

## 决策

### 1. 产品边界：情报主轴，预测冻结

1. 新增“情报中心”，默认交付为一页每日决策摘要；另提供全球雷达、事件簇、证据链和全球态势地图。
2. 现有预测页面、合同版本、21 格结果、formal 状态、OOS 门禁、评分、账本和 API 语义全部冻结。实施只能新增导航、页面、API 和数据表，不能借情报中心重命名、回填、重算或提升预测状态。
3. 情报可独立展示可能影响、方向、传导时间和证据强弱，但必须把“来源事实”和“系统推断”分字段保存和显示；不得伪装成确定事实、数值预测或采购/交易指令。
4. 情报中心未来若要成为预测特征，必须另立 ADR，并先完成 point-in-time、泄漏检查、消融试验和逐格 OOS 晋级；v37 不建立该数据通路。
5. v37 的来源项目、事件修订和日报均由数据库约束固定 `prediction_eligible=0` 与 `instruction_eligible=0`；应用层不能通过参数放宽。

### 2. 宽雷达、窄摘要

系统广泛采集和索引全球经济、地缘与军事安全、制裁、能源、生产装置、航运与港口、极端天气、自然灾害、基础设施、贸易物流及重要官方新闻。全量合格信号进入“全球雷达”，供主动检索和地图浏览。

每日摘要不是全量新闻流。只有与七品种产业链、原料采购、供应中断或到货风险达到版本化相关性门槛的事件簇才能进入主摘要，并优先排序：

1. 供应中断、装置异常、港口/航线/运河受阻；
2. 原油与能源冲击、制裁、战争和地缘升级；
3. 极端天气、灾害和关键基础设施故障；
4. 能影响需求、汇率、成本或贸易流向的宏观事件；
5. 其他全球信号保留在雷达中，不挤占每日摘要。

主摘要按事件簇而不是文章计数。每个核心事件至少包含：事实摘要、首次与最近可见时间、原始来源及转载关系、证据等级、与本产业链的相关理由、传导路径、受影响品种、可能方向、D1/D7/D30 观察窗口、置信度、反证、未知项和后续观察项。相互冲突的来源并列保留，不以多数转载自动提高置信度。

### 3. 独立 append-only v37 数据域

v37 新建与预测、legacy Phase A 和现有新闻表语义隔离的工业情报域。该域可以通过稳定 ID 引用已有新闻或观测，但不得更新其原记录，也不得向预测表写入任何内容。

计划的数据合同至少覆盖：

- 原始证据快照及其 canonical payload、SHA-256、collector/aggregator/origin 来源身份、原始 URL、抓取/发布时间、`visible_at` 和解析器版本；
- 稳定事件簇，以及只追加的聚类成员关系和事件分析 revision；
- 事实、推断、冲突、反证、影响路径、品种关联、时间窗口和置信度的分离投影；
- 按上海业务日冻结的日报版本、信息截止时间、输入快照清单、生成器版本和 payload hash；
- 地图对象与事件 revision 的时间绑定，而不是无来源的当前坐标覆盖。

所有业务事实以 canonical JSON 和内容哈希为权威，查询列只是有界投影。数据库 trigger 禁止对已发布的证据、事件 revision 和日报执行 UPDATE/DELETE；纠错、合并、拆分、撤销和来源修订一律追加新 revision 或 invalidation，不改写历史。重复采集、重复聚类和同一日报重试必须幂等；相同稳定 ID 但内容冲突时失败关闭。

迁移必须支持全新库、v36→v37、重复启动和对象身份校验，并在迁移前建立经 `integrity_check`、外键检查、权限和哈希校验的 v36 备份。上述内容是实施合同，不表示 v37 已存在。

### 4. 来源目录由现有注册表派生

现有核心 `source_registry.json` 继续决定来源治理、身份和运行配置，现有 `NEWS_SOURCES` 只补充新闻 connector 与内容分类。情报中心对两者做只读派生和去重；重叠来源以核心 registry 的治理字段为准，分类或等级漂移必须显式暴露。目录投影派生来源名称、类型、URL/host、更新节奏、可信等级、成本/凭据状态、抓取能力、最后尝试/成功、数据质量、适用条款和处理限制，不得成为第三份可独立编辑的来源配置。每份日报必须保存当日用于 readiness/选择的安全规范目录快照、条目数和 SHA-256，不能只指向会继续变化的当前 registry。

调度、健康度、详情页和日报引用都使用稳定 `source_id`。投影缺失或陈旧时应显示 unavailable/degraded，不得以手写前端数据补齐。新增正式 provider 必须声明自己的来源能力并进入核心注册表，再由目录和情报流水线消费。

DCE 与 CCF 的既有条目继续保持 `soft_removed`：目录可以显示其历史身份和禁用原因，但 v37 不调度、不采集、不投影为当前情报，也不能把它们计入 readiness。重新启用仍需新的明确决策和 ADR。

### 5. God's Eye View 只作选择性复用

不 fork 为第二套服务，不整仓合并，不使用 iframe 作为产品边界。只在逐文件审查后复用其 MIT 许可允许的通用交互、图层组织或 UI 思路，并将必要的小段代码移植到现有 React/FastAPI 架构；保留版权与许可声明。

God's Eye View 仓库引用的第三方数据、瓦片、图标、影像、密钥、代理配置和资产不因其代码采用 MIT 许可而自动可复用。它们必须作为独立来源重新登记、核对适用条款并通过本项目的出站 host allowlist 和凭据边界。未完成此过程的上游图层不得进入生产。

### 6. 地图基线为 MapLibre + Natural Earth

首版全球态势层使用 MapLibre GL JS 渲染，并以 Natural Earth 的公开域基础地理数据提供零密钥底图/边界基线。地图是理解事件位置、航线、设施和影响范围的辅助视图，不是默认首页，也不是事实来源。

首版不依赖 Cesium、Google Maps 或其他必须配置 token、启用账单或按量付费的地图服务。任何高精度瓦片、卫星影像、实时船舶/航空或商业地理服务只能作为关闭状态的可选增强；未配置时不得降低情报中心基础 readiness。

### 7. 零强制新增付费

基础采集、事件聚类、每日摘要、证据链和基础地图必须在没有新增付费 API、订阅或商业密钥时可运行。已有模型供应商是否产生费用沿用现有配置和降级边界，不因本 ADR 扩大授权。

可选付费源必须显式标为 optional、默认关闭、隔离配额并显示成本状态。缺少可选密钥只能造成对应图层/来源 unavailable，不能阻断基础日报；系统也不得通过绕过登录、付费墙、CAPTCHA、robots/技术限制或伪装身份来满足零成本目标。

### 8. 来源条款和证据治理

本项目是单操作者工作台，但服务于生产经营和采购研判，不能仅因使用者只有一人就自动视为非商业用途。公开可见数据不需要内部 license/manifest 人工审批后才能进入技术评估；但网页公开可见也不自动授予复制、长期保存、再分发或商业使用权。来源身份、署名、许可/服务条款、允许的缓存与再展示范围、抓取频率和访问边界必须转成机器可执行的运行元数据。条件不满足时自动降为链接/元数据、禁用或明确缺口，不恢复已废止的人工许可仪式。

代码许可与数据许可分别判断。若来源条款不支持保存或再展示完整正文/高精度数据，系统只保存允许的元数据、内容哈希和原始链接；仅在策略明确允许时才保存来源摘录或派生事实摘要，并必须区分二者。日报与事件不保存第三方正文或长摘录；前端不得把受限内容打包成公开数据集。来源条款变化通过核心 registry/connector 版本变更和后续日报内的完整目录快照记录，不建立可独立编辑的第三份目录，也不回写历史权利快照。当前与未来的展示、索引、缓存、采集和再分发必须立即按新策略收敛；有限保留期原文放在可过期对象区，到期清除后追加 tombstone/invalidation，而不删除 append-only 业务事实。当前读模型对历史 rights snapshot 和当前策略取更严格值，受限字段只做带原 payload hash 的派生脱敏展示；权利清理未完成时搜索失败关闭。任何再分发、共享式 SaaS 或扩大使用主体都超出本 ADR，必须重新审查来源和地图资产。

证据等级继续沿用项目现有治理：官方/一手来源优先，经过独立佐证的来源其次，发现型来源只能形成待确认信号，不能单独支撑高置信结论。来源中的文本一律视为不可信数据，不能作为 Agent 指令执行。

### 9. API 与认证边界

情报中心使用 `/api/v1/intelligence/*` 下的版本化、类型化合同，并同步维护 `docs/api.md`、`docs/openapi.yaml` 和前端 client 类型。计划的读面至少覆盖最新/历史日报、事件列表与详情、来源目录和地图要素；响应必须暴露合同版本、as-of/cutoff、数据状态、事件/证据 revision、来源引用及事实/推断区分。

所有抓取、导入、聚类、重算、日报冻结、纠错/invalidation 和操作者反馈属于内部操作。它们必须先通过现有内部鉴权：loopback 浏览器使用 HttpOnly local-session cookie，服务器自动化使用 `X-Internal-Token`；浏览器不得包含构建时内部 token。公网访问继续受现有单用户密码代理、Secure/HttpOnly/SameSite 会话、Origin 和 CSRF 边界保护，代理在转发前剥离调用方伪造的内部认证头。

普通 GET 必须保持只读，不能隐式抓取、补算、冻结日报或调用付费模型。错误继续使用带 `request_id`、稳定 `code`、`message` 和 `details` 的标准 envelope；接口不得返回密钥、完整受限原文或服务端代理凭据。

### 10. 发布节奏与无即时提醒

每日摘要沿用上海时区生产节奏：08:20 信息冻结，09:30 发布。全球雷达可以在用户主动打开时展示其已采集的较新状态，但不得静默改写已冻结日报。

本阶段明确不提供即时提醒：不发送短信、邮件、系统通知、ServerChan/PushPlus、Webhook 或事件触发推送，即使事件被评为高风险也只在下一份日报或用户主动打开页面时出现。相关代码不得借用现有告警渠道。若未来需要即时提醒，必须单独决策其严重度、证据门槛、去重、冷却、静默时段和误报责任。

## 回滚

情报中心必须具备独立 feature flag/导航开关和独立 writer。发生来源污染、聚类异常、日报错误或地图故障时，先停止情报 writer 并关闭情报入口；预测及其他既有功能继续运行，不读取 v37 情报数据。

应用发布采用不可变 release。部署 v37 前停止会写 SQLite 的生产进程，创建并校验 v36 备份，再执行迁移和 smoke。若新 release 失败但旧 release 明确兼容 v37，可仅切回 release；否则必须停止 writer、保全故障库副本、恢复经校验的 v36 备份后再启动旧 release。禁止删除 v37 表或修改 `user_version` 来伪装兼容，也不得把 v37 事件倒灌进预测或旧新闻表。

情报内容纠错不采用数据库回滚：追加 invalidation/替代 revision，历史日报保持可重放。只有迁移或发布失败才使用数据库备份恢复。

## 后果

- 产品默认价值从“先看一个尚待时间验证的预测”转向“先得到经过压缩、可追溯、与产业链相关的全球情报”，同时避免为提升观感而篡改预测科学门槛。
- 广泛采集会增加来源维护、解析器漂移、存储和相关性评估成本；窄摘要会产生漏报风险，因此保留可检索的全球雷达和完整证据链。
- 事件聚类和影响路径仍可能误合并、误关联或遗漏。置信度、反证和修订历史用于暴露不确定性，不能消除它。
- 不提供即时提醒意味着接受从事件发生到日报发布之间的延迟；本系统不是应急预警、航行安全或军事态势指挥工具。
- MapLibre + Natural Earth 降低密钥和成本依赖，但首版地图精度、实时性和视觉效果会弱于商业底图或完整 3D 地球。
- 零强制付费保证基础能力可持续运行，但不保证所有全球信号都有实时、完整或高精度覆盖；可选数据缺失必须诚实展示。
- append-only v37 提升点时审计和日报重放能力，也带来额外存储、迁移、备份和 revision 查询复杂度。
- 选择性复用 God's Eye View 能吸收空间产品经验并控制技术风险，但需要逐项移植、测试和许可记录，不能把上游热度视为生产成熟度。
