## 1. 目标、范围与最终产物

从个人工作台使用者出发，回答：能否快速找到信息、完成操作、理解结果和追溯证据；系统能否在没有人工补跑的情况下持续收集、更新、处理和交付数据。

覆盖当前公网全部一级模块、二级视图、弹窗、抽屉、图表、表格及可操作组件。下面的菜单是起始清单，执行时必须依据真实界面增补 Zcode 新增或改名的功能。功能确实移除时记录现行产品理由；不能把找不到的入口直接判为通过或不适用。

交付物：

1. 当前版本、审计时间、环境及授权范围。
2. 完整页面和组件覆盖矩阵，以及每项实测结果。
3. 用户体验与性能记录：原始耗时样本、失败样本、截图和动作。
4. 七类正式产品的价格、指标、新闻、证据覆盖矩阵。
5. 自动任务清单、预期运行机会与实际运行记录对账、自然运行稳定性结论。
6. 带独立证据的问题清单、100分评分、发布判定和最多10项优先行动。
7. 未验证事项、限制及需要补充的外部条件。

审计执行者不得把“部署成功”“HTTP 200”“能打开页面”“队列显示成功”当成全链路通过。

## 2. 产品边界与操作约束

- 本系统是单人工作台，不按商业多租户 SaaS 的注册、计费、组织管理要求扣分。
- 正式预测产品为原油、石脑油、PX、PTA、MEG、POY、DTY，周期1/7/30天。Brent/WTI可作为原油子基准，不能把八个采集标的当成八种正式预测产品。
- 预测保留，但信息收集、聚合、证据组织和工业情报同样属于核心价值。个人库存、采购量、成交价和加工利润不作为预测目标。
- DCE、CCF保持软移除，历史记录可保留；不得因当前不调度而重复扣分。确认无残留正式调度或误用历史数据。
- EIA密钥不作为先决条件；若生产已接入，需审计其实际数据质量。禁止读取或在报告中展示密钥。
- 公共来源不设额外许可审批流程；不得绕过登录、验证码、付费墙或其他访问控制。
- 当前公开访问是用户接受的产品边界；不因“没有密码”本身扣分。仍检查秘密是否暴露、正常参数限制、写操作反馈和资源使用是否可控，不进行攻击测试。

### 审计模式

默认只读：导航、搜索、筛选、排序、分页、展开、缩放、刷新、打开来源链接、下载已存在的公开报告。下载若会触发生成，按写操作处理。

AI提问、生成报告/摘要、保存预测、正式采集、重试任务、导入、修改设置等先登记副作用。按该执行会话已有的明确授权决定能否执行，不重复索取已经覆盖的授权；不得把“开始审计”推定为可以任意写生产数据。

授权写入样例应限定模块、品种、请求次数、预期产物及成本边界，并记录生成ID。未授权时标“需要写入授权后验证”，不中断其他只读检查。不要为清理测试痕迹擅自删除数据。

不修改代码、不提交、不推送、不迁移或直接访问生产数据库、不部署、不重启生产、不人为中断网络或外部来源。不通过生产故障注入来证明恢复能力。

## 3. 证据方法与执行顺序

### 3.1 主证据

必须使用 Computer Use 控制用户 Chrome，亲自进入、点击、滚动、刷新和检查。入口重定向以真实最终URL为准。

- Chrome/Computer Use无法连接：记录阻塞，停止界面审计，不能以API或源码冒充完成。
- 如果出现登录：停在登录页请用户手动登录；不读取密码、钥匙串、Cookie、Local Storage等凭据。
- 开始记录时间、Chrome版本、窗口尺寸、页面缩放、网络情况及前后端版本标识。版本变化时分批记录，不把两个版本结果混为一组。
- 可辅以只读公网API、响应头、DevTools和经授权的脱敏运行日志/指标。源码只用于解释原因和核对部署，不能作为功能通过证据。
- Console/Network不可读就明确标未验证。不能写“无错误”。禁止采集含凭据的完整请求头、令牌或未经脱敏的HAR。

### 3.2 执行顺序

1. 建立页面树、组件清单、来源清单和自动任务清单；所有结果先置为“未验证”。
2. 完成公网入口、版本、会话和基础健康检查。
3. 按第6节逐模块执行；每两个一级模块汇报一次已验证内容、问题和下一步。
4. 运行跨模块用户流程、竞态与键盘/窄窗口检查。
5. 对账数据源、观察时间、持续性及自动任务记录。
6. 对不一致和严重问题重复复现；保留失败证据，继续检查不受影响模块。
7. 对证据和评分做一次复核，再出具结论。没有覆盖全部范围不得声称全量完成。

若用户明确要求建立goal，目标应包含全部模块覆盖和最终证据交付；未验证项必须在结论里保留，不能为关闭goal伪报完成。

### 3.3 通用组件检查卡（每页必填）

| 组件/维度 | 实际操作 | 通过条件 |
| --- | --- | --- |
| 标题、导航、面包屑 | 点击进入、返回、复制URL重开 | 标题、高亮、内容与URL一致，返回位置符合预期 |
| 按钮/链接 | 测每个不同作用按钮，含禁用态 | 有实际结果或明确禁用原因；无死按钮、假成功 |
| 搜索 | 中文、英文、空值、前后空格、无结果；清除并恢复 | 结果与查询匹配，清除可恢复；回车与搜索按钮一致 |
| 筛选/排序 | 单条件、组合、切换、重置 | 计数和结果同步；排序语义正确，不保留无效选中项 |
| 表格/列表 | 翻页、末页、加载更多、返回上页 | 无漏项/重复、总数诚实；翻页后选中详情不指向旧条目 |
| 标签页/折叠项 | 展开关闭、切换再返回 | 内容真实、状态可理解，无旧数据串页或布局跳动 |
| 弹窗/抽屉 | 打开、关闭、Esc、键盘焦点返回 | 内容不遮挡，焦点不逃出模态层，关闭后回到原控件 |
| 图表 | 悬停、图例、区间、缩放、切换品种 | 数值、日期、单位和系列一致；少数据诚实降级 |
| 文本/提示 | 阅读短/长标题、缺口、错误与说明 | 中文易懂，无调试术语/内部路径/占位字；截断内容可查看 |
| 状态 | 实际观察加载、空、部分失败、恢复 | 不白屏、不无限转圈；失败不显示成功，能合理恢复 |
| 证据 | 打开引用、返回、核对原文 | 链接指向支持该主张的内容，非首页/错误页或无关文章 |

没有出现的失败/空状态可在隔离测试环境补验，必须标明环境；生产正常样本不能证明失败状态通过。有限数据库不要求遍历全部记录，但所有组件类型和页面入口必须覆盖，抽样范围必须写明。

## 4. 交互体验与性能测量

### 4.1 统一计时

每个主要页面至少做5次普通读取：首次会话进入1次、再次进入2次、普通刷新1次、强制刷新1次。写操作不为凑样本重复执行。主链路跨模块切换至少5次。外部来源请求保持低频，不做压力测试。

记录三个时间点：T0发起动作、T1首次可感知反馈、T2主要内容完整且可操作；异步任务另记T3结果完成。API耗时只作补充，不能替代T2−T0。Computer Use工具整体耗时不能直接当网页耗时；无法准确测时则记录工具采样区间或人工近似值，注明精度。

普通刷新和强制刷新不等于后端冷启动；不得通过重启生产来制造冷启动。首次访问、浏览器资源缓存、服务端缓存状态能识别多少记录多少，未知则写未知。

下列为本轮建议验收线，并非声称已经达标；执行开始时冻结，不得事后为高分放宽：

| 场景 | 建议验收线 | 严重体验问题 |
| --- | --- | --- |
| 点击/切换反馈 | ≤0.3秒有视觉反馈 | >1秒完全无反馈、用户易重复点击 |
| 本地筛选/已载入标签 | ≤0.5秒完成 | >2秒卡住或阻断其他操作 |
| 普通模块主要内容 | 重复读取中位数≤2秒，最慢≤5秒 | 常见操作>10秒、反复超时或旧数据误导 |
| 首次地图/重图表 | ≤5秒可用；1秒内显示加载状态 | 长时间无反馈、阻塞其他模块、退出后继续弹错 |
| AI/生成任务 | ≤1秒确认已受理；AI首个有用输出建议≤5秒、完成建议≤30秒 | 假进度、超时无终态、重复提交产生重复任务 |
| 已有报告打开/下载 | 建议≤5秒 | 误触生成、空文件、无法打开 |

AI阈值应优先使用当前版本已被用户接受且有记录的基线；没有基线时上述数值仅用于发现待讨论问题。快但无依据的回答不能通过，慢也不能只凭一次偶发样本判系统故障。

每页记录原始样本、中位数、最慢值、成功/失败次数及反馈质量。5次样本不报告可靠P95；日志若覆盖足够样本，可另给窗口、N值和P95。失败样本不得从分母删除。

### 4.2 对抗操作与易用性

- 快速切换三种品种、连续切换多个模块，检查响应乱序、旧标题配新数据、取消后结果覆盖新查询。
- 直接地址栏访问深层视图，再前进/后退；检查参数、筛选、选中项和滚动恢复。
- 常规桌面约1440×900，窄窗口约768×900；另在桌面检查125%和200%缩放。记录实际可达尺寸；工具不能安全调整则标未验证。表格内部横向滚动可接受，核心按钮被挤出页面不可接受。
- Tab/Shift+Tab/Enter/Space/Esc检查核心导航、搜索、筛选、弹窗、分页；焦点必须可见且顺序合理。
- 空结果、长标题、超长引用、少量数据和多页记录均抽样。关键内容不能只靠颜色表达，不能被悬浮助手遮挡。
- 不模拟并发压力；快速操作限制为正常用户频率，验证界面竞态而非制造服务器负载。

## 6. 逐模块执行卡

模块URL按真实导航确认；以下 `module` 值为定位线索，不是已验证接口承诺。所有执行卡均须加做第3.3节通用组件检查及第4节计时。

### M01 总览看板（module=overview）

1. 读取今日结论、风险、链路价格、关注事项、来源覆盖、数据更新时间及最新运行摘要。
2. 点击每类指标卡、风险条目、快捷入口，检查进入正确品种/事件/报告，返回后上下文合理。
3. 展开长结论与证据，核对“今日”使用的业务日期及是否引用旧报告。
4. 与行情、事件、报告逐项对账至少3个指标；确认不是多个模块各取不同时间而未解释。
5. 检查无新数据、部分来源失败时是否明确区分历史参考和当前判断。

通过要求：看板能支持“今天发生了什么、依据是什么、下一步去哪里”，关键数字能追溯。保留整页和关键指标证据。

### M02 行情与原料链（module=market）

1. 逐一切换原油、石脑油、PX、PTA、MEG、POY、DTY，原油展开Brent/WTI等实际子基准。
2. 检查链路节点、最新价、时间、来源、单位、图表、规格明细、近期参考报价、库存、开工率及加工差。
3. 操作30/90日等实际区间、图例、悬停和历史分页；从链路节点切换与产品选择器切换结果应一致。
4. 当前报价与历史序列分开核对：现货/期货代理/公开估值，规格、地区、币种和汇率日期不一致时不得直接拼接或算涨跌。
5. 新报价到达后刷新，核对价格卡、观察信号、解释、更新时间和滞后项数量同步；若没有自然新报价，只能验证静态一致性。
6. 检查休市、节假日、周度指标，不能仅按分钟年龄把正常休市误判抓取故障，也不能借休市掩盖漏采。
7. 核对库存天数与库存吨数、聚酯开工与某品种开工、加工差与净利润，禁止混名和混口径。

通过要求：7类产品逐个留数据行；新鲜度与真实观察时间一致；历史不足诚实显示，旧规格不冒充当前规格。

### M03 事件与风险（module=events）

1. 搜索中文、英文、来源名、产品名；类别组合筛选，清空，分页/加载更多。
2. 选不同来源、日期、摘要状态的事件，核对列表选中态与详情一致。
3. 展开事实摘要、影响研判、证据核验、相似事件、是否改变今日判断等实际组件。
4. 抽查英文来源中文摘要至少5条：数字、主体、时间、单位及结论逐句对照原文；区分事实与推断。
5. 检查只有标题、正文受限、错误页、校验失败、正在处理等记录，不得“100%生成”却输出模板或伪造细节。
6. 核对转载去重、来源独立性、行业缩写歧义及发布日期精度；发现时间不能冒充原文发布时间。
7. 打开原始来源和相似事件后返回，检查上下文及结果数。

通过要求：每种实际摘要状态至少取样；事实准确和引用匹配优先于文字流畅与覆盖率。

### M04 证据图谱（module=evidence）

1. 切换实际图谱模式、品种或主题；搜索节点、点击节点/边、查看详情和来源。
2. 拖拽、缩放、复位、图例开关、全屏等控件逐项使用；检查窄窗口可操作性。
3. 沿“结论→事实→原文”追踪至少3条链；检查边方向、关系类型和时间含义。
4. 比较同一事件在列表和图谱的事实、来源、置信度；无证据关系不能视觉伪装为已证实。
5. 检查空图/少节点/大图及异步返回时布局、选中详情和响应时间。

通过要求：图谱既能读懂也能追溯，不是只画节点和连线。记录点开的节点ID与URL。

### M05 Agent系统／运行状态（module=workflow，按现名）

1. 逐个进入Agent、工作流、任务、步骤、历史运行和错误详情等实际二级入口。
2. 核对运行中、成功、部分成功、失败、跳过及等待的语义；检查运行ID、起止时间、输入输出计数。
3. 从一条完成运行追踪到价格/事件/报告产物；失败后查看下一次自然运行及积压变化。
4. 确认页面刷新不会触发业务任务；“重试/执行/抓取”等按钮在有授权时仅运行限定样例。
5. 对照第9节自动化矩阵，检查实际启用任务是否都能被观察，状态是否来自真实执行。

通过要求：成功必须有可解释产物或合理无变化结果；跳过、失败不得被聚合为成功。

### M06 AI研判助手（module=assistant）

读取既有会话可只读验证；新提问及会话保存按实际副作用和授权处理。

1. 使用已有会话检查历史列表、切换、滚动、长回答、引用跳转和返回。
2. 获准后分别提出：当前价及日期、某事件影响、两来源冲突、无证据问题。保存问题、上下文日期和回答ID。
3. 测量受理、首个有用内容、完成时间；检查流式显示、停止/取消、超时和失败恢复（只有实际出现才判）。
4. 核对每个关键数字与引用；不把会话记忆里的旧价当最新，不以高置信语气掩盖证据不足。
5. 检查多轮追问中的产品、期限和用户意图保持；切换会话不能串上下文。
6. 不因历史单次耗时已获接受而免测当前部署，但不随意更改已接受基线。

通过要求：回答可读、可追溯、日期清晰，等待过程可理解；没有测新提问就不能写“AI端到端通过”。

### M07 研判报告（module=reports）

1. 逐个检查日报、周报、信息报告及当前新增类型；筛选、日期、列表、详情和返回。
2. 打开最近和历史报告，对照形成时间、业务日期、来源截止时间、版本与正文；历史不应装作今日。
3. 展开图表、事实、推断、预测、证据、附件、下载/复制等组件；已有文件下载后核对内容与页面一致。
4. 生成/发布/保存按钮仅在明确授权下执行，验证完成ID、产物与历史列表，而非仅看toast。
5. 无可用数据时不输出“成功空报告”；归档不可被只读打开或刷新重写。

通过要求：报告内容和引用可核验，阅读/生成/发布行为界限清楚。

### M07-B 预测账本与到期复盘（二级视图，不得遗漏）

1. 从研判报告实际入口进入，验证深链接、返回和导航高亮。
2. 逐类筛选7产品×1/7/30天；核对已发、未到期、已到期、已复盘、无法复盘状态及计数。
3. 抽查预测发布时间、基准价、目标日期、方向/区间、证据快照和模型版本，不能使用事后数据。
4. 对到期记录核对预测时与评估时的价格口径一致；展示命中、误差及样本数的分母正确。
5. 未到期、不存在合格实绩或样本不足时明确保留空值；不能以0误差或100%命中替代未知。
6. 保存预测、手动复盘有副作用，授权后再执行；优先验证已有自然到期记录。

通过要求：账本管理和复盘逻辑可独立通过；预测准确率另列自然到期证据，不用短期样本承诺模型效果。

### M08 工业情报中心（module=intelligence）

**每日摘要**

- 查看当前业务日、最近历史日、切换返回、刷新状态和重点事件。
- 分别核对收集窗口、截止、计划发布、实际发布、无达标事件、部分覆盖、受阻。
- 检查重点事件、影响矩阵、覆盖域、观察项、引用及缺口说明；有效证据过滤后，API和页面状态必须一致。
- 日报标识/归档哈希跨只读访问不变；质量重审可以改变展示，但不得伪称归档被重新生成。

**全球雷达**

- 操作搜索、时间、类别、地域、品种等现有筛选、排序和分页。
- 点击事件，核对摘要、正文证据、地点、日期、来源、影响与返回路径。
- 相同报道不重复放大热度；“无相关事件”和抓取失败要区分。

**运行与来源**

- 浏览全部来源页和全部运行类型；检查最近尝试、最近成功、最新有效数据、计数、耗时及失败原因。
- 区分来源可访问、解析成功、内容相关、摘要通过、入库成功、最终被日报采用六个阶段。
- 不因HTTP200或零条目就标覆盖良好；列出失败、超期、停用、历史保留和凭据条件。

**全球态势地图与惰性加载**

- 首次不打开地图，检查地图资源是否延后加载（Network不可读时此项未验证）。
- 首次打开计时，操作标记、聚合点、缩放、拖拽、图例、筛选、详情跳转及返回。
- 再次打开检查是否重复加载、丢失状态或重复标记；快速离开地图不能弹出延迟错误覆盖其他页面。
- 无坐标时不能默认落在0,0或随意给位置；地图事件总数与筛选结果的差异要解释。

通过要求：四个子视图分别结论；地图截图不能代替验证惰性加载。

## 8. 数据真实性、覆盖与持续性

### 8.1 价格与指标矩阵

每个产品、来源和价格基准分别一行，不用产品级“有价”掩盖规格缺口：

| 产品/规格/地区 | 来源/原文 | 价格类型 | 数值/单位/币种 | 原始观察时间 | 发布时间 | 采集/入库时间 | 页面快照 | 应更新节奏 | 当前延迟 | 连续性/缺口 | 结论 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 待实测 | | | | | | | | | | | 未验证 |

- 采集时间、系统读取时间和原文观察时间分别记录；重复读取旧内容不能推进有效数据日期。
- 单位换算保留原始值、汇率日期/来源和换算规则；不拿期货代理替代同规格现货而不说明。
- 对账最新点、前一有效点及缺失段；检查异常跳变、重复日期、未来日期、连续常数值和采集停摆。
- 日内数据按交易时段，日频按实际发布/交易日，周频按发布日历计算预期；自然日不机械等于数据机会数。
- 供需指标单列库存、开工、装置、产量、贸易等实际字段；未公开发布、账号受限、解析失败分别归类。

### 8.2 新闻来源矩阵

| 来源 | 覆盖品种/地域/主题 | 类型/独立发布者 | 最近尝试 | 最近成功读取 | 最新相关原文日期 | 相关条目数 | 可核验正文数 | 合格摘要数 | 最终采用数 | 失败/缺口 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 待实测 | | | | | | | | | | |

来源清单与各阶段计数全量核对。原文抽样至少覆盖每个活跃来源的最新相关条目（若有），核心来源增加正常和失败/边界样本；标明总量和样本量。对只返回首页、目录、错误页、搜索摘要的来源不能计完整正文。转载、RSS和搜索结果回指同一发布者只算一组独立证据。

### 8.3 推荐观察窗口与指标

- 近24小时：可发现正在发生的中断，不能单独证明长期稳定。
- 近7个自然日且包含业务日/周末边界：日常持续性；版本刚发布不足窗口时如实给实际天数。
- 近30天：趋势和长间隔任务；周频来源至少看3次应发布机会。新版运行不足时，旧版本记录只作旁证。
- 预测效果按真实到期样本另算，不以观察窗口替代到期。

定义并报告分母：

- 任务执行覆盖率＝有可归属运行记录的预期执行机会/全部预期执行机会。
- 按时完成率＝期限内完成的预期机会/全部预期机会；合理无变化可以完成，漏跑不从分母删掉。
- 有效数据新鲜达标率＝满足来源发布节奏和容忍延迟的观测/应检查观测。
- 端到端交付率＝成功到达预期消费者的应交付批次/全部应交付批次。
- 摘要覆盖同时报告“全体条目”和“具备合格正文的条目”两种分母；错误页、受限正文不能从报告中消失。

## 9. 自动化与后端稳定性 Review

先从当前运行界面、只读指标和任务配置建立真实清单，不能只检查文档列出的名称。候选包括价格采集、官方数据更新、新闻发现、正文补全、中文摘要、情报投影/聚类、每日情报摘要、日报/周报、预测到期评估、索引更新、健康探测、告警和备份；实际未启用的注明原因，不虚构任务。

| 任务 | 启用状态/唯一调度入口 | 频率/时区/日历 | 预期执行机会 | 实际尝试/完成 | 最近有效产物 | 队列/重试/最长等待 | 失败及恢复 | 证据窗口 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 待核实 | | | | | | | | |

每项检查：

1. **无人值守真实性**：区分定时、手动、启动补跑和重试，手动成功不替代定时成功；重复安装的调度入口不能互相掩盖漏跑。
2. **完整执行链**：开始→获取→校验→保存→消费→页面显示。HTTP200、进程存活、心跳更新不代表业务完成。
3. **唯一性与重试**：同一业务日期/输入/任务键重复执行是否重复生成；部分成功后重试是否只处理未完成部分。通过既有记录或隔离测试证明，不在生产制造重复任务。
4. **排队与卡死**：最长运行、最长等待、重试次数、永久processing、锁未释放、积压趋势；每条失败有可归属原因和终态。
5. **时序和截止**：UTC/上海转换、周末节假日、漏跑补偿、晚到数据。回补不覆盖冻结日报，不让截止后的数据进入当时预测。
6. **依赖故障**：外部限流/超时、AI失败、源内容未变、模型文件不可用、索引故障如何影响主服务；降级是否保留可用功能且不伪报成功。
7. **启动与恢复**：读取已有重启记录，测实际不可用窗口、ready恢复及产物恢复；是否依赖联网下载模型，是否每次重启重复执行任务。没有真实重启证据则未验证，不主动重启生产。
8. **资源与持续性**：可用时读取进程重启计数、CPU/内存、磁盘、数据库锁、连接池与查询延迟的窗口记录；单点快照不能证明无泄漏。禁止未经授权直连生产数据库。
9. **宿主机约束**：核对实际部署形态；若依赖个人电脑，检查已有睡眠、网络切换、断电记录和恢复行为，不宣称云级持续在线。
10. **告警**：故障检测时间、送达记录、恢复通知、去重和误报。只读核对已有通知，不擅自发送测试消息。
11. **备份**：最近成功备份、保留策略及已有隔离恢复验证；“有备份文件”不等于“可恢复”。不复制生产数据库来补审计证据。

稳定性必须分别给“当前可用”“观测窗口内持续运行”“已验证故障恢复”三个结论，不能合并成一个绿色状态。

## 10. 问题严重度与扣分归属

- **P0**：不可接受的数据破坏、严重泄密、全局不可用或无法信任的核心数据错误。
- **P1**：核心用户流程阻断、关键数字/时间误导、自动任务持续漏跑、失败伪报成功、多核心模块不可用。
- **P2**：可绕行的功能/交互问题、明显延迟、局部数据或证据缺口、窄窗口和键盘使用障碍。
- **P3**：不影响核心完成的小型文案、间距、一致性问题。

严重度按实际影响和持续范围判定；一次重启502不自动等于全局长期故障，也不能因为后来恢复就删掉。

每项扣分只归一个原因类别：A代码/界面；B部署/配置；C密钥/账号/用户输入；D外部恢复或官方数据；E自然运行/预测到期证据；F已接受产品边界；G尚需取证。F原则上不扣分，单独列明不追分；不能把程序缺陷归成F。症状可影响多个维度，但同一验收失败不得重复扣分。

问题记录模板：

| 字段 | 内容 |
| --- | --- |
| ID / 严重度 / 分类 | |
| 模块、子视图、URL、版本 | |
| 时间、环境、前置条件 | |
| 复现步骤 | 可逐步执行，包含输入与控件 |
| 期望 / 实际 | 数值或可观察行为，不用“感觉慢” |
| 用户影响 | |
| 原始耗时与失败次数 | |
| 截图/响应/运行ID证据 | |
| 稳定复现 | x/y次，或仅一次尚未复现 |
| 根因 | 已证实 / 推测；不要混写 |
| 建议与验收办法 | 最小改动建议，不在审计中擅自修复 |

## 11. 评分与发布判定

| 评分维度 | 分值 | 必须有的证据 |
| --- | ---: | --- |
| 公网可达性、会话和版本一致性 | 10 | 入口/刷新/深链/访问策略/版本/健康 |
| 全部模块及组件的功能完整性 | 24 | 页面树、组件清单、实际交互与结果 |
| 交互体验、可访问性和窗口适配 | 14 | 主流程、焦点、窄窗口、缩放、状态反馈 |
| 反应时间、网络和生产整洁度 | 12 | 原始样本、失败记录、Console/Network可读范围 |
| 数据真实性、时效性、连续性和追溯 | 22 | 两类来源矩阵、原文样本、时间/口径及窗口 |
| 自动化稳定性、恢复和可观测性 | 18 | 预期/实际对账、产物、积压、依赖与恢复证据 |
| **合计** | **100** | |

执行前把各维度分值分配至具体检查ID并冻结权重；新增菜单在维度内调整且留记录，不能出分后调权重。评分表必须同时列“已得分、确认缺陷失分、未验证失分”，三者合计100。所有未验证项不给证据分，不简单把通过项平均为总分。

预测功能、账本和评估方法属于功能评分；预测准确率单独列出样本和结果，不作为本轮产品工程总分承诺。来源覆盖和自动化稳定性不能通过排除自然日证据获得满分。

- **NO-GO**：存在P0；无法进入主体；核心数据明显错误；多个核心模块不可用；或关键交付持续失败且无法恢复。
- **GO WITH WARNINGS**：无P0，主流程可用，仍有P1、显著覆盖缺口或关键持续性证据不足。
- **GO**：无P0/P1，核心交互和数据证据完整，自动化满足约定观察窗口，仅剩有限P2/P3。
- 对未覆盖关键范围只能给“暂定判定”，不能给正式GO。可以上线不等于100分，修复上线也不等于所有缺口关闭。

另列：可立即修复问题数/总问题数；不依赖自然日可追回分数；依赖外部事实/自然日分数；无需追分的接受边界。每个分数要回指检查ID和问题ID。

## 12. 最终报告结构与交付复核

最终报告按以下顺序输出：

1. 一句话结论、实际版本、时间、当前分数和发布判定。
2. 覆盖矩阵：每个一级/二级视图及新增入口的通过、部分通过、失败、未验证。
3. 主用户流程与交互体验结果。
4. 响应时间矩阵、网络/控制台观察及测量限制。
5. 逐模块问题清单，按P0至P3排序。
6. 价格/指标及新闻来源矩阵，数据时效性和连续性结论。
7. 自动化任务矩阵及观察窗口，当前可用与稳定性分别下结论。
8. 跨模块一致性、预测账本与到期证据。
9. 距离100分的逐项扣分、A–G归属和可追回分数。
10. 最多10项按用户收益/成本排序的行动，每项有验收标准。
11. 截图、响应、日志片段和运行记录索引。
12. 未验证事项及原因，包括未授权写操作、工具不可读、外部限制和自然日不足。

证据目录建议 `agent-context/public-module-review-<实际执行日期>/`。每个一级模块至少一张截图，工业情报四个子视图和预测账本独立留图；P0/P1各有独立证据。记录文件绝对路径、时间、SHA-256、字节数、对应检查ID及是否脱敏。

最后自检：每个“通过”是否有实际动作及正确结果；每个严重问题是否可复现；是否混用了不同版本；是否漏了隐藏在抽屉/二级页的功能；是否把无数据、受限数据和程序失败混在一起；是否误把一次成功写成可持续。

**本方案编写完成不意味着审计执行完成。当前所有检查结果均待实测。**
