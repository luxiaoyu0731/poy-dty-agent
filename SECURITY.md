# Security

Do not post API keys, database exports, personal information or actionable exploit details in public issues.

Report a vulnerability privately using GitHub's **Report a vulnerability** feature when available. If it is unavailable, contact the repository owner through an existing private channel and share details only after a private route is agreed.

The repository includes secret scanning, static security rules and dependency checks. Run the checks again for your deployment; an old scan is not evidence that a new configuration is safe.

Use your own credentials, isolated databases and explicit source allowlists. Never bypass authentication, paywalls or CAPTCHAs. The public demo is a read surface, not permission to test destructive behavior against the production service.
